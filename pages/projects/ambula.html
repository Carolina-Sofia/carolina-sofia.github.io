Ambula

Project Overview

Ambula is a platform designed to simplify transportation scheduling and management, specifically focusing on ambulance services. I developed it as a solo project for my 3-month internship at Ambula, handling everything from front-end UI to back-end architecture and database integrations.

Key highlights:

  • Multi-step scheduling flow – leveraging Node.js/Express, EJS templating, and session management.
  • Third-party integrations – with Google Maps for distance calculations, Airtable for data/pricing, and IfThenPay for secure payments.
  • Production-ready – managing real user bookings and payments.

Key Features

  • Comprehensive Scheduling Process: A multi-step flow (pickup/destination, user data, transport details, payment) ensuring user data is collected, validated, and stored efficiently.
  • Dynamic Pricing: Real-time fare calculation based on distance (Google Maps) and configurable pricing variables (Airtable).
  • Secure Payment: Integration with IfThenPay to generate references (Multibanco, PinPay), recording transactions and statuses in Airtable.
  • Responsive UI & Validation: User-friendly forms with real-time checks and progressive data storage (session-based).

Multi-Step Workflow

Ambula’s scheduling is split into distinct EJS views, each collecting necessary data while updating both session and Airtable records:

  1. Step 1: Pickup/Destination/Date/Time → Saves in session.
  2. Step 1.1: User details → Creates/updates a “Utilizadores” record, then creates “Agendamento” in Airtable with status Simulação.
  3. Step 2: Pricing summary (distance-based) → Option for round-trip (+ discount logic), updates Agendamentos with initial price.
  4. Step 3: Personal/beneficiary details (age, gender, etc.) → Links “Beneficiários” or “Utilizadores” to the “Agendamento.”
  5. Step 4: Transport type (ambulance/adapted vehicle) & extras selection → Adjusts final price, updates Airtable.
  6. Step 5: Final confirmation → Summarizes all details, updates Agendamento with final transport choice and notes.
  7. Step 6: Payment selection → Integrates IfThenPay, creates new “Transações” record with status Pendente, updates Agendamento to Espera.

My Contributions (Solo Project)

  • Full-Stack Development: From front-end EJS templates, form validation, and session flow to Node.js backend architecture and routing.
  • Airtable & Google Maps Integration: Managing database operations (CRUD), dynamic distance-based pricing, and real-time data sync in Airtable.
  • IfThenPay Payment Flow: Generating and validating payment references (Multibanco, PinPay), updating transaction statuses in Airtable, and handling server callbacks.
  • Ongoing Maintenance & Debugging: Set up robust console and error handling, responding to real-time user feedback for iterative improvements.

Challenges & Learnings

  • Complex Third-Party Integrations: Ensuring seamless data flow among Google Maps, Airtable, and IfThenPay without blocking or crashing the Node server.
  • Multi-Step Session Workflow: Ensuring partial user data is always available at each step while maintaining data integrity in production.
  • Scalability & User Feedback: Continually refining the interface and logic based on real-time usage data and new feature requests.

Project Impact

  • Improved Efficiency: Automated scheduling drastically reduced manual phone calls and paperwork.
  • Enhanced User Experience: The step-by-step interface simplified complex forms, improving user satisfaction.
  • Real-World Monetization: IfThenPay integration enabled seamless digital transactions, boosting revenue collection.
  • Robust & Scalable: The platform can handle higher volumes of appointments and payments as the service expands.
